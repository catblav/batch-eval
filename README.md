# 黑猫-自动评测台

本地桌面工具。填好自己的 LLM API，批量跑评测数据，按评测提示词给出的分类统计结果。
（更新）新增自动脚本，接入agent可自动跑测评数据，自动迭代提示词。

支持win和mac。

![分析页](docs/screenshots/05-analysis.png)


## 安装

从 [Releases](https://github.com/catblav/batch-eval/releases/latest) 下载对应平台的安装包。

### Windows

下载 `Heimao-AutoEval_0.1.3_x64-setup.exe` 运行安装。

### macOS

下载 `Heimao-AutoEval_0.1.3_macOS_universal.dmg`，打开后把应用拖进 Applications。包里同时有 Apple Silicon 和 Intel 两种架构。

安装包没有做 Apple 公证，第一次打开要**右键点图标选打开**。如果系统仍然拦截，在终端执行：

```bash
xattr -cr "/Applications/黑猫-自动评测台.app"
```

## 使用

界面分五个页面，按顺序操作。

### 1. API 配置

填两个模型的 Base URL、API Key 和模型名。

被测模型负责生成输出，评测模型负责逐条判定。判定要求稳定时，评测模型用 temperature 0。

协议选 OpenAI 兼容或 Anthropic。其它可配项有上下文长度、max_tokens、temperature、top_p、超时、自定义请求体和请求头。填完可以点 **测试连接** 验证。

页面底部是「自动迭代脚本」，点「复制引导语」得到一句发给 agent 的话，详见 [自动迭代脚本](#自动迭代脚本)。

![API 配置](docs/screenshots/01-api.png)

### 2. 提示词

主体提示词是被测模型的 system prompt。

用户消息模板用 `{{列名}}` 注入数据列的值。

评测提示词是裁判模型逐条调用的内容，必须包含 `{{input}}` 和 `{{output}}`。

页面下方会实时显示实际发送给 API 的完整内容，方便检查变量替换是否正确。

![提示词](docs/screenshots/02-prompts.png)

### 3. 数据集

导入或粘贴数据。格式支持 CSV、TSV、Excel、JSON、JSONL 和纯文本。

编码自动识别，UTF-8 读不出来时按 GB18030 再试一次。

勾选需要注入的列，会自动生成用户消息模板。列名里包含 `数据组状态` 时，会把它当作**分组列**，运行页和分析页按它分组。

![数据集](docs/screenshots/03-dataset.png)

### 4. 运行

设置并发数和失败重试次数，点开始。

运行过程中可以看到每一条的通过状态、分类和原因，也可以中途取消。

结果会增量写入磁盘。中断后重新打开，点 **断点续跑** 只补没跑完的部分。失败项可以单独重跑。

![运行](docs/screenshots/04-run.png)

### 5. 分析

顶部是通过率、通过和不通过的条数、错误分类数量、平均响应时间。

中间是错误分类分布，按条数排序，点分类可以筛选。

下面是明细表，支持按结果、分组、分类筛选和关键词搜索。**点任意一行**打开详情，能看到原始数据、实际发送的消息、被测模型的输出、裁判模型的原始输出和判定原因。

![分析明细](docs/screenshots/06-detail.png)

## 自动迭代脚本

### 用途

如果你在用 Claude、Codex 这类 agent 工具，把这个脚本交给它，agent 就能帮你自动跑提示词测试，并根据测试结果持续修改提示词。

### 使用方法

1. 下载并安装「黑猫-自动评测台」。
2. 打开「① API 配置」，页面底部是「自动迭代脚本」，点「复制引导语」，把这句话发给 Claude、Codex 这类 agent：

   > 请读取 `<安装目录>/auto-iterate/guide_agent.md`

剩下由 agent 引导：指定工作目录、配置 API、放提示词和数据集，然后读文件、跑测试、改提示词。

### 建议

第一次建议自己先跑一遍，配置好 API、提示词和数据集，确认能正常出结果。之后就可以让 AI 帮你批量跑、自动改。当然，如果使用脚本，AI 也会读取使用说明教你配置好。

## 数据处理

评测分类完全来自评测提示词输出的 `errorType`，工具本身不内置任何分类。

**只有三种情况**会用工具自带的分类，并且和用户分类分开统计：

- 被测模型调用失败
- 评测模型调用失败
- 评测输出解析失败

裁判模型返回的内容不一定是标准 JSON，可能包在代码块里，或者字段名写成 `error_type`。解析时先剥代码块，再按括号配平提取 JSON，最后做字段名大小写和同义词兼容。都解析不出来才归到「评测输出解析失败」。

输入超过上下文的会做截断，保留头 60% 和尾 40%，详情里会标记。

## 数据存储

配置和数据都在本地用户目录下：

```
Windows:  %APPDATA%\com.batcheval.app\
macOS:    ~/Library/Application Support/com.batcheval.app\
```

```
settings.json               配置、提示词、列选择、主题
dataset.json                数据集
runs/current/meta.json      当前运行的元信息
runs/current/results.jsonl  每跑完一条追加一行
```

**只保留当前一次运行**，重新跑会清空上一次的结果。

**API Key 明文保存在本地**，不会发送到其它地方。

## 详细功能

### API 配置

- **被测模型**和**评测模型**分开配置，可以填同一个 API，也可以分开
- 支持 OpenAI 兼容协议和 Anthropic 协议
- 可配上下文长度、`max_tokens`、`temperature`、`top_p`、超时、自定义请求体与请求头
- 填完可点「测试连接」验证；400 / 401 / 404 / 429 / 503 会翻译成中文原因和处理建议
- 「测速」发 3 次短请求，给出实际延迟和 tok/s，用来区分慢在模型排队还是慢在本工具

### 提示词

- 主体提示词作为被测模型的 system prompt
- 用户消息模板用 `{{列名}}` 注入数据列
- 评测提示词包含 `{{input}}`（被测模型收到的提示词 + 本条输入）和 `{{output}}`（被测模型的实际输出）
- 页面下方实时预览实际发送给两个模型的三段内容，变量替换错了当场能看出来
- 「恢复默认」先预览再覆盖，避免误点丢掉改好的提示词

### 数据集

- 支持 CSV、TSV、Excel、JSON、JSONL 和纯文本
- 编码自动识别，UTF-8 读不出来时按 GB18030 再试
- 勾选注入列自动生成模板；列名含 `数据组状态` 时按它分组
- 超量数据和坏行都有提示

### 运行

- 并发调用，遇到 429 / 503 自动降速重试，带抖动退避
- 连续多条调不通会自动叫停，避免把整批数据白跑完
- **断点续跑**：中断后只补没跑完的部分
- **失败项重跑**：不用整批重来
- **取消立即生效**：在途请求直接中止，不等超时
- 结果增量落盘，崩溃或取消都不丢；实时结果可分页查看

### 分析

- 通过率按有效样本计算，调用失败 / 模型超时 / 解析失败单列为「未计入」，不拉低通过率
- 结果按评测提示词输出的 `errorType` 聚合，分类分布可点击筛选
- 明细表支持按结果、分组、分类筛选和关键词搜索，分页 50 / 100 / 200
- 点任意一行看详情：原始数据、实际发送的消息、被测输出、裁判原始输出、判定原因
- 详情里有两侧的 token 用量和裁判生成速度，定位耗时花在哪一段

### 导出

- 导出 CSV 或 JSON，支持大结果分块写盘
- 导出完整报告：一个 xlsx，包含概览、错误分类、明细三个 sheet，带标题条、指标卡、状态色和冻结表头

### 自动迭代

- 自动迭代脚本和说明随应用安装
- 「① API 配置」页底部一键复制 agent 引导语
- 脚本负责调用被测模型、按裁判提示词判分、和上一版对比、归档提示词；agent 负责读文件、定参数、改提示词
- 只用 Python 标准库，Python 3.8 以上即可，不需要装依赖

### 安装与界面

- Windows 安装完成自动创建桌面快捷方式
- 亮 / 暗双主题，选择持久化
- 窗口按内容定宽，可自由拉伸

## 开发

需要 Node 18 以上、Rust stable，以及 Tauri 对应平台的系统依赖。

```bash
npm install
npm run tauri dev
```

打包：

```bash
npx tauri build
```

Windows 会生成 exe 和 NSIS 安装包。macOS 的构建配置在 `.github/workflows/build-macos.yml`，推送 tag 自动构建 dmg。

前端用 Vue 3、Vite 和 Tailwind，后端用 Rust。

## 测试

```bash
cd src-tauri
cargo test --lib
```

端到端测试需要先启动 mock 服务：

```bash
node ../tests/mock-api.mjs
cargo test --lib -- --ignored --nocapture
```

压测时在项目根目录生成一万行数据集，再让 mock 服务变慢并按比例失败：

```bash
node tests/gen-dataset.mjs 10000
MOCK_DELAY_MS=300 MOCK_FAIL_RATE=0.05 node tests/mock-api.mjs
```
